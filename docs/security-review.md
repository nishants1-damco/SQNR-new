# Security review (Phase 5)

The review before cutover asked for in plan §16.3, done on 2026-10-01 against this repo (API, worker, packages, `infra/azure`). It focuses on auth flows, SAS issuing and tenant isolation, plus the edge, dependencies and data deletion. It was done by reading the code and running the test suites. It is not a penetration test, and nothing has been deployed to Azure yet.

## Reviewed and found sound

- **Tokens.** Ed25519 JWTs with the algorithm, issuer and audience pinned on verify. Key rotation keeps the previous public key in the JWKS.
- **Refresh tokens.** They rotate, and a replayed token revokes its whole family. They are stored hashed, and the cookie is `HttpOnly`, `Secure`, `SameSite=Strict` and limited to `/v1/auth`. Refresh and sign-out also check `Origin` against `WEB_ORIGINS`.
- **Passwords and email links.** Passwords use argon2id and are rehashed on sign-in when the parameters change. Sign-in gives one answer for an unknown account, a wrong password and a disabled account. Email tokens are hashed, single-use and expire. The password-reset request always succeeds from the caller's point of view.
- **Rate limits.** Auth limits are per IP and per account, and fail closed. Quotas are in Redis and fail closed. The request throttle (per user, and per IP for anonymous requests) fails open. Analysis has daily spend caps and queue backpressure.
- **Tenant isolation.** Every route is classified in `test/route-policy.ts`, and the suite fails on an unclassified route. Tenant-scoped routes answer 404 to other users, never 403. Cross-wired ids are covered (for example, deleting another user's frame through your own scan). Queries always filter on `user_id`, and the raw SQL fragments come from fixed maps.
- **Uploads (SAS).**
  - Upload URLs are create-only (no overwrite, read, list or delete), bound to a content type, and live 15 minutes.
  - Completion checks that every file exists, its size is within limits, and its stored content type matches.
  - The worker sniffs the bytes, removes non-images and strips EXIF/GPS from JPEGs.
  - Read URLs are read-only and live one hour.
  - In Azure, storage has shared keys disabled; URLs are user-delegation SAS signed with the API's managed identity.
- **Input and output.** Every body, query and parameter goes through Zod, and response schemas strip unknown fields. JSON bodies are capped at 1 MB. Error envelopes hide server details, and logs redact `Authorization`, `Cookie` and `Set-Cookie`.
- **Headers and CORS.** Helmet is on (HSTS, nosniff, frame denial). CORS uses an explicit origin list with credentials. The SPA ships a strict CSP generated at build time (SQNR-web). Swagger is off in production.
- **Outbound requests.** Geocoding goes only to the fixed Nominatim URL, with the query encoded and a global one-per-second slot. Catalog photos are covered in S7. The model is called through the Anthropic SDK. Nothing fetches a URL taken from a user.
- **Infrastructure.**
  - Secrets live in Key Vault, read by managed identities.
  - Postgres, Redis, Key Vault and the registry are private (VNet and private endpoints).
  - The app's database role has DML only; migrations use a separate role.
  - Images run as the non-root `node` user, and production mode refuses development defaults.
  - The WAF runs in Prevention mode with managed rules in production.
  - Deployment uses GitHub OIDC; there are no stored Azure credentials.
